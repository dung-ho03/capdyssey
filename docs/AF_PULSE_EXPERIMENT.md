# 맥박 특징과 정렬 진단 실험

## 변경 이유

전처리 구조 검사는 통과했지만 기존 손목 모델의 낮은 구별 능력은 해결되지 않았다.
필터링하지 않은 자기상관/주파수 특징도 손목 검증 AUC가 약 0.5에 머물렀다.
따라서 저주파 흔들림과 고주파 성분을 줄이고 맥박 간격 특징을 추가하는 실험을 한다.
0.5–5Hz, 3차 Butterworth, 양방향 필터와 반사형 경계 확장 100점은 이번 실험의
고정 공학 설정이며 이 자료에서 최적 또는 임상적으로 검증된 값이라고 주장하지 않는다.

## 입력과 비교

- 기존 10초/50Hz PPG, 동일한 피험자 분할, 세 자료 통합 학습을 유지한다.
- 중간 8초에서 양·음 방향의 봉우리를 각각 검출한다. 두 방향 특징을 모두 모델에
  제공하며 ECG나 정답을 보고 모델 입력의 방향을 선택하지 않는다.
- 간격 변동계수, 연속 간격 차이, 분위수, 검출 수, 검출 실패 표시 등을 추가한다.
- 충분한 봉우리를 찾지 못한 구간도 버리지 않는다. 실패 표시와 자료별/정답별
  실패율을 남겨 평가 대상에서 제외해 성능이 좋아 보이는 일을 막는다.
- 모델 학습·추론은 Colab GPU에서만 실행한다. SciPy 필터/봉우리 추출도 Colab에서
  실행되지만 CPU 배열 연산이다. 로컬 컴퓨터에서 데이터 처리·학습을 하지 않는다.
- 두 seed(42,43), 최대 20 epoch, patience 5, AdamW 0.0005를 사전에 고정한다.
- 모든 자료의 검증 특이도 80% 이상을 만족하는 공통 임계값에서 자료별 평균
  민감도를 최대화한다. 시험군은 읽지 않는다. 기존 검증군 재사용이라는 제한을 유지한다.

## ECG–PPG 진단 범위

학습/검증 피험자별·정답별 최대 12구간을 seed 42로 추출한다. 제공 QRS와
검출한 PPG 봉우리의 양방향 일치율을 비교한다. ±0.5초 범위에서 위상 차이를
탐색하고 0초와 ±10/±30초의 비교 구간을 함께 기록한다.
주기적인 파형은 다른 시간대도 일치할 수 있으므로 이 수치만으로 동기화를 확정하거나
시계를 자동 보정하지 않는다. ECG 간격 변동은 설명용으로만 저장하며 학습 특징에
절대 넣지 않는다. 전체 원본 파형이나 모든 박동을 임상적으로 판독하는 검사는 아니다.

### 다음 진단을 하는 이유

학습/검증에서 선택한 손목 621개 구간의 간격 변동계수 중앙값은
ECG에서 비AF 0.0244 / AF 0.2287, PPG에서 0.2548 / 0.2808이었다.
ECG에서 보이는 차이가 현재 PPG 봉우리 특징에서는 약하다.
이는 파형 품질·검출기·시간 정렬을 추가로 살펴볼 근거이며,
어느 하나가 원인이라고 확정하거나 원본 데이터 전체를 불신할 근거는 아니다.
±10/30초 이동에도 중앙 일치율이 약 0.43–0.47로 비슷하므로,
현재 진단만으로 시간 이동값을 정해 라벨을 옮기지 않는다.

일치율 0.8 이상 구간은 비AF 30/341, AF 1/280이었다.
이 사후 기준으로 구간을 제외하면 AF를 훨씬 많이 버리므로
이를 품질 기준으로 채택해 전체 성능이 개선되었다고 보고하지 않는다.
ECG 기반 일치율은 PPG만 들어오는 실제 추론의 품질 판정에도 사용할 수 없다.

저장 결과 `alignment_examples.png`의 원본 ECG/QRS와 PPG를 확인한 다음,
검출기 오류와 실제 신호/시각 문제를 구분하는 추가 검사를 설계한다.
현재 단계에서는 기존 체크포인트를 연구 후보로 보존하고 최종 배포 모델로 승격하지 않는다.

### 원본 표본 재현 검사

Colab T4와 Drive를 재연결한 뒤, 각 잠정 라벨에서 일치율 최저·중앙·최고
구간을 골라 원본 PPG의 해당 10초만 다시 읽었다. 6개 모두 저장된 필터 파형과
일치했다(최대 절대 오차 약 2.33e-7). 전체 데이터의 추가 전수 검사는 아니다.
그림에서는 일부 원본의 큰 급변, AF 표본에서 규칙적인 PPG와 다른 ECG 형태가
보였다. 원본에도 존재하는 현상이며, 이것만으로 움직임·센서 오류·시각 오차 중
어느 원인인지 확정할 수 없다. 비교 그림의 PPG 표시 봉우리는 양의 방향이고
보고서 일치율은 양·음 방향 중 최댓값이므로 둘을 동일한 검출 결과로 보지 않는다.

Drive에 `raw_reproduction_report.json`, `raw_reproduction_examples.png`를 저장했다.

### 참가자별 오류와 임계값 진단

seed 42의 저장 검증 예측을 분석했다. 손목 7명 중 AF가 존재하는 6명의
민감도는 009: 63.33%, 022: 8.54%, 024: 0%(AF 7개뿐),
028: 6.40%, 036: 47.15%, 037: 42.46%였다. 012는 AF가 없어
민감도를 계산할 수 없다. 022·028의 FN 3,082개가 전체 손목 FN 4,665개의
약 66%를 차지한다. 후속 신호/시각 진단의 우선 대상이며 이들을 제외하지 않는다.

손목 검증 민감도 90%를 만족하도록 사후 임계값을 약 0.0820으로 낮추면
손목 특이도는 **14.12%**(비AF 오탐 약 85.88%)로 떨어진다.
같은 임계값의 MIMIC 민감도/특이도는 100%/78.33%,
6종은 97.62%/59.42%다. 민감도 숫자만 높이려는 임계값 변경으로는
문제가 해결되지 않는다. 이 값은 배포 설정으로 채택하지 않았다.
Drive `sensitivity_diagnosis.json`에 저장했다. 시험군은 이번 진단에 사용하지 않았다.
