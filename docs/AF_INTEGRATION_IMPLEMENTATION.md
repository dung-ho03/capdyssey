# 세 자료 통합 코드와 실행 범위

## 2026-10-12 런타임 소실 후 재개 방식 변경

재연결한 Colab에서 `REPO_EXISTS False`, `WRIST_FILES 0`, `BUNDLES []`를 확인했다. 이전 39명 다운로드 완료 기록과 024번까지의 전처리 출력은 남아 있지만, 새 런타임에는 해당 파일이 없다. 이 변경은 모델 성능 개선 결과가 아니라 작업 유실을 줄이기 위한 저장 방식 변경이다.

- 노트북 04는 Google Drive의 `MyDrive/Capdyssey/af_integrated`에 원본, 전처리 결과, 실행 결과를 저장한다. Google 연결 승인과 충분한 실제 Drive 용량이 필요하다. 런타임의 디스크 용량 표시는 Drive 계정의 남은 용량을 보장하지 않는다.
- 전처리는 기록별 NPZ 저장을 마친 후 `checkpoint.json`을 갱신한다. `--resume`은 원본 파일과 전처리 코드의 SHA-256 및 저장된 결과 체크섬을 확인하고 완료 기록을 재사용한다. 중단된 기록은 다시 처리한다. 같은 출력 폴더를 두 런타임에서 동시에 처리하지 않는다.
- 원본이나 코드가 바뀌면 기존 결과를 섞지 않고 새 출력 폴더를 요구한다. 이전 방식으로 생성한 체크포인트 없는 폴더는 자동 복구하지 않는다.
- 기존 `/content` 파일을 Drive 저장으로 되살릴 수는 없다. 이번에는 원본을 다시 받아야 한다. Drive 승인 전에는 대용량 재다운로드를 시작하지 않았다.
- 손목 정답 코드와 시간별 라벨 연결은 여전히 미완료다. 공식 v3 설명은 박동별 AF 주석과 동기화를 설명하지만 숫자 코드별 의미는 명시하지 않는다. 라벨 -1을 임의로 0/1로 변환하지 않는다.

검증: 노트북 Python 문법 검사 통과. 기존 합성 테스트 4개 통과; 새 체크포인트 테스트는 Windows 샌드박스의 임시 파일 이름 변경 권한 오류로 실행 완료하지 못했다. 권한 확대 재실행은 승인되지 않았으며, Colab에서 실제 재개 검증이 남아 있다. 모델 학습이나 성능 평가 완료를 뜻하지 않는다.

2026-10-10. 목표: 세 자료의 10초 PPG로 Colab에서 통합 학습·평가. 기존 MIMIC 단독 학습을 반복하지 않는다.

## 이번 변경과 이유

- `prepare_af_integrated.py`: MIMIC·6종·손목 v3를 동일한 10초/50Hz/500샘플 NPZ와 manifest로 구성한다. 데이터셋 이름을 포함한 참가자 ID, 기록 ID, 시작 시각, 제외 수, 출처 체크섬을 보존한다.
- 6종은 원본 10초 구간과 원래 리듬 코드를 보관한다. 연속 시각을 모르므로 시작 시각을 NaN으로 명시하고 구간을 이어 붙이지 않는다.
- 손목은 헤더 시각 기준 ECG와 완전히 겹치는 10초만 준비한다. 숫자 주석 코드의 의미를 모르므로 정답을 **-1(미확정)**로 보관한다. 이것을 비AF로 치환하지 않는다. 준비가 완료되어도 감독학습용 정답이 완성된 것은 아니다.
- `train_af_integrated.py`: Colab에서만 실행하는 별도 통합 학습기다. 자료 누락·미확정 정답·사용 범위 미확인·자료별 참가자 부족을 검사하고, 실패하면 MIMIC 단독으로 자동 전환하지 않는다.
- 실행 조건이 충족되면 학습 자료에서만 자료/클래스/참가자 비중을 계산하여 샘플링한다. 세 자료별 검증 손실 평균으로 epoch를 선택하고 자료별 시험 지표를 저장한다. MIMIC은 기존 참가자 분할을 보존한다. 다른 자료의 고정 분할에서 클래스가 사라지면 중단하며 시험 성능을 보고 seed를 골라 재분할하지 않는다.

이용 조건과 라벨 문제가 해결되기 전까지 통합 학습기는 실행 완료 또는 성능 검증 완료로 표시하지 않는다. 설정 플래그 변경만으로 미확정 라벨 문제가 해결되는 것도 아니다. 현재 준비 함수는 손목 라벨을 항상 -1로 출력하므로 코드북 확보 후 실제 시간별 정답 연결을 구현해야 한다.

## 전체 39명으로 확대하는 이유와 실행 방법

사용자 요청에 따라 손목 자료는 표본 2명이 아니라 공식 v3 전체 39명을 준비한다. 소수 참가자에게 치우친 학습을 피하고 참가자별 분할을 준비하기 위한 변경이다. 데이터 확대만으로 과적합 해소나 정확도 향상이 입증된 것은 아니다.

- 다운로드 옵션 `--all`: 001~039 ECG·PPG 쌍 78개와 부속 2개 파일, 총 63,713,598,681바이트. 공식 목록의 39명 및 파일 쌍을 검사한다.
- 완료 파일은 MD5 검증 후 재사용, 부분 파일은 이어받기. 동일 저장 공간이 유지되는 경우에만 재개 가능하다. Colab 런타임 삭제 시 `/content` 파일은 소실된다. 원본 외 전처리 공간도 필요하다.
- Colab에서 최신 코드를 가져오고 다운로드·전처리 진행 로그를 셀에 표시한다. 전처리 후 손목 39명 모두에 유효 구간이 있는지 검사한다.
- 숫자 정답 의미·시간 정렬 확인은 별도 과제다. 전체 대상 확대를 완료된 학습이나 성능 검증으로 표시하지 않는다.

로컬 검증은 전체 다운로드 계획(네트워크 다운로드 없음), 노트북 코드 문법 검사다. 실제 다운로드·전처리·학습은 Colab에서 진행한다.

실행용 Drive 사본도 전체 39명 코드로 수정하고 모두 실행했다. Colab 준비 셀에서 `CODE_VERSION db0aeb106fc4fbdad48457a9946e1301a68fc40e`를 확인했고, 다음 셀에서 MIMIC 다운로드 안내가 출력됐다. 전체 손목 다운로드 완료나 전처리 완료는 아직 확인하지 않았다. 합성 입력 및 미확정 라벨 차단 테스트 3개는 통과했다(모델 학습 아님).

## 2026-10-12 빈 날짜 처리 수정

Colab에서 39명 다운로드·체크섬 완료 후 전처리가 `int(day)`에서 실패했다. 전체 39명 PPG 날짜 필드를 Colab에서 검사한 결과 003의 기록 인덱스 0, 1, 2는 `MATLAB_empty=1`인 빈 문자 배열이었다. 저장값 [0,0]은 날짜가 아니라 빈 배열의 차원 정보다.

빈 날짜를 인식하도록 수정했다. 해당 기록은 버리거나 날짜를 추정하지 않고 10초 파형과 y=-1을 보존하며 시작 시각은 NaN, `alignment_ready=false`, ECG 겹침은 unknown으로 기록한다. 이 구간은 ECG 기반 정답 연결에 사용할 수 있다고 주장하지 않는다. 다른 기록은 기존 시간 겹침 검사를 유지한다. 39명 포함은 파형 준비 범위이며 39명 모두의 정답 연결 완료를 뜻하지 않는다. 다운로드를 재실행하지 않고 전처리만 다시 실행한다.
