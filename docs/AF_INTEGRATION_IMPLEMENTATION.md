# 세 자료 통합 코드와 실행 범위

2026-10-10. 목표: 세 자료의 10초 PPG로 Colab에서 통합 학습·평가. 기존 MIMIC 단독 학습을 반복하지 않는다.

## 이번 변경과 이유

- `prepare_af_integrated.py`: MIMIC·6종·손목 v3를 동일한 10초/50Hz/500샘플 NPZ와 manifest로 구성한다. 데이터셋 이름을 포함한 참가자 ID, 기록 ID, 시작 시각, 제외 수, 출처 체크섬을 보존한다.
- 6종은 원본 10초 구간과 원래 리듬 코드를 보관한다. 연속 시각을 모르므로 시작 시각을 NaN으로 명시하고 구간을 이어 붙이지 않는다.
- 손목은 헤더 시각 기준 ECG와 완전히 겹치는 10초만 준비한다. 숫자 주석 코드의 의미를 모르므로 정답을 **-1(미확정)**로 보관한다. 이것을 비AF로 치환하지 않는다. 준비가 완료되어도 감독학습용 정답이 완성된 것은 아니다.
- `train_af_integrated.py`: Colab에서만 실행하는 별도 통합 학습기다. 자료 누락·미확정 정답·사용 범위 미확인·자료별 참가자 부족을 검사하고, 실패하면 MIMIC 단독으로 자동 전환하지 않는다.
- 실행 조건이 충족되면 학습 자료에서만 자료/클래스/참가자 비중을 계산하여 샘플링한다. 세 자료별 검증 손실 평균으로 epoch를 선택하고 자료별 시험 지표를 저장한다. MIMIC은 기존 참가자 분할을 보존한다. 다른 자료의 고정 분할에서 클래스가 사라지면 중단하며 시험 성능을 보고 seed를 골라 재분할하지 않는다.

이용 조건과 라벨 문제가 해결되기 전까지 통합 학습기는 실행 완료 또는 성능 검증 완료로 표시하지 않는다. 설정 플래그 변경만으로 미확정 라벨 문제가 해결되는 것도 아니다. 현재 준비 함수는 손목 라벨을 항상 -1로 출력하므로 코드북 확보 후 실제 시간별 정답 연결을 구현해야 한다.

## 추가 조사

연구진 Pluščiauskaitė의 [2025년 학위논문 3.2.3절](https://biomedicine.ktu.edu/wp-content/uploads/sites/237/2025/07/2025_Disertacija_Plusciauskaite-V.pdf)은 ECG 검출 후 의료진이 주석을 검토하고 AF 외 리듬도 주석 처리했다고 설명한다. 하지만 v3 파일의 숫자별 코드 정의는 이 근거에서 확인하지 못했다. 구버전 연구 설명을 v3 숫자 매핑으로 추정 적용하지 않는다.

## 실행

[Colab 통합 준비·학습 노트북](https://colab.research.google.com/github/dung-ho03/capdyssey/blob/main/notebooks/04_af_integrated_colab.ipynb)

기본 대상: MIMIC 35명, 6종 91명, 손목은 확보 대상으로 정한 006/039 2명. 전체 39명 학습이 아니다. 공식 출처에서 Colab으로 직접 받고 체크섬을 검증한다. 참가자별 최소 5명 및 양 클래스 검사는 이 초기 분할 프로토콜의 기술적 하한일 뿐 충분한 검증 표본을 보장하지 않는다.

현재까지 로컬에서 수행한 것은 합성 신호를 이용한 전처리·미확정 정답 차단 테스트 3개와 노트북 문법 검사다. 로컬 모델 학습 또는 성능 평가는 하지 않았다. 통합 학습기의 학습 루프는 아직 실행 검증되지 않았다. Colab 실제 준비 결과는 실행 후 아래에 별도로 기록한다.

## 2026-10-11 재개 확인

[실행용 Drive 노트북](https://colab.research.google.com/drive/1g_-lbbu6mR39TsM4p3J4zAHphUBc8bOB)의 저장된 출력에서 다음 두 줄을 확인했다.

```text
CODE_VERSION fa3eb69233c704b2f42cf5b29a1ca5b9d77b0c18
THREE_SOURCE_DOWNLOADS_COMPLETE; wrist subset=2/39
```

이는 이전 실행의 다운로드 완료 출력이다. 현재 세션에 파일이 남아 있다는 확인이나 전체 손목 39명 확보를 뜻하지 않는다. 전처리 셀의 `PREPARATION_SUMMARY`와 학습 조건 검사 출력은 저장되어 있지 않았다. 따라서 준비된 구간 수와 통합 성능은 아직 보고하지 않는다.

모두 실행으로 재개했지만 Colab은 `연결 중 / 런타임 할당 중`에 머물렀고 세션 관리에는 `런타임 연결이 끊어짐`이 표시됐다. 페이지의 연결용 프레임 로딩 시간 초과도 관찰했다. 이 관찰만으로 계정 한도나 서버 장애 등 근본 원인을 특정할 수 없다. 로컬 CPU 학습으로 전환하지 않았다.

다음 순서: Colab 호스팅 런타임 연결 → 다운로드 재검사 → 10초 전처리 요약 확보 → 정답 코드·시간 정렬 확인 및 필요한 참가자 확대 → 통합 학습·자료별 평가. 연결 복구와 별도로 손목 정답 코드 확인은 여전히 필요하며, 데이터의 임상적 신뢰성 부족과 정답 파일 해석 미완료는 구분한다. 이번 기록은 실행 근거를 명확하게 남기기 위한 문서 변경이며 새로운 모델 성능 개선 결과가 아니다.
