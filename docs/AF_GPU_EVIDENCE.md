# 민감도 개선 근거를 얻기 위한 GPU 비교

사용자 요청에 따라 이후 학습/모델 평가는 CUDA GPU가 없으면 중단한다.
Colab에서 Tesla T4를 확인하고 수정된 10초 전처리 자료를 재사용한다.
원본 다운로드·재전처리는 반복하지 않는다.

## 질문과 비교 조건

1. 기존 centered 모델의 검증군에서 임계값 .5의 민감도/특이도와 전체 점수
   분포를 확인한다. 90% 민감도일 때 특이도, 80% 특이도일 때 민감도를
   고정된 .001 간격 그리드로 산출한다. 두 수치는 진단용 목표이며 임상 기준이 아니다.
2. MIMIC+6종, 손목 단독, 세 자료 통합을 모두 같은 GPU에서 새로 학습한다.
   CPU에서 학습했던 모델만 대조군으로 쓰지 않는다.
3. 동일 참가자 분할, 전처리, 모델, seed 42, 배치 64, 학습률 .001,
   회차당 전체 통합 학습군 수만큼 표본 추출, 최대 20회/patience 5를 적용한다.
   자료/클래스/참가자별 가중치 정책은 유지한다. 소규모 자료는 반복 추출된다.
4. 각 모델은 학습에 포함한 자료들의 평균 검증 BCE로 체크포인트를 고른다.
   선택 기준의 대상 자료가 달라지는 효과와 단일 seed의 한계를 함께 기록한다.
5. 세 자료 모두의 검증 결과를 보고하되 손목 단독 모델의 MIMIC/6종 결과와
   두 자료 모델의 손목 결과는 학습하지 않은 자료로의 이전 결과라고 구분한다.

시험군은 이번 스크립트에서 읽지 않는다. 체크포인트와 임계값 선택에 같은
검증군을 재사용하므로 이 수치를 최종 독립 성능이라고 부르지 않는다.
자료 혼합이 문제인지, 손목 자체의 학습이 어려운지 판단하는 개발 실험이다.
AF_annotation의 정확한 0/1만 쓰는 잠정 해석은 유지된다.

## 저장

Drive `Capdyssey/af_integrated/models/gpu_source_evidence_v1/`에
protocol.json, existing_model_validation.json, 각 조합의 모델·학습 이력·검증 예측,
comparison.json을 저장한다. 실행 로그는 상위 폴더의 gpu_source_evidence_v1.log.
`scripts/af_gpu_evidence.py --base <Drive 경로>`로 실행하며 GPU 없이는 시작하지 않는다.
완료된 조합은 재사용하지만 중단된 조합의 optimizer 이어학습은 지원하지 않는다.

## 실제 GPU 비교 결과

Tesla T4에서 세 조합 완료(`GPU_EVIDENCE_COMPLETE`). 최선 회차는 두 자료 7,
손목 단독 2, 통합 6이다. 평가 구간은 검증군 MIMIC 838, 6종 11,118,
손목 20,417개이며 아래 수치는 기존 시험 결과와 직접 비교하지 않는다.

| 학습 조합 | MIMIC AUC | 6종 AUC | 손목 AUC |
|---|---:|---:|---:|
| MIMIC+6종 | 0.9061 | 0.8664 | 0.4518 |
| 손목 단독 | 0.4437 | 0.4562 | 0.5129 |
| 세 자료 통합 | 0.9043 | 0.8889 | 0.5234 |

각 자료에서 특이도 약 80%를 만족하는 별도 진단용 임계값의 민감도:

| 학습 조합 | MIMIC | 6종 | 손목 |
|---|---:|---:|---:|
| MIMIC+6종 | 91.6% | 83.2% | 14.0% |
| 손목 단독 | 31.8% | 2.4% | 20.5% |
| 세 자료 통합 | 89.7% | 85.3% | 23.5% |

이는 자료별로 서로 다른 임계값을 사용한 진단표로, 이 세 수치를 동시에 내는
하나의 공통 배포 임계값을 찾았다는 뜻이 아니다. 학습하지 않은 자료에서의
수치는 전이 평가다. 단일 seed/검증군 비교여서 우열의 통계적 확정도 아니다.

손목 민감도를 90%로 올리면 손목 단독 특이도는 15.0%, 통합은 11.6%에 그쳤다.
단순히 판정 기준을 낮춰 손목 문제를 해결할 수 있다는 근거는 없다.
손목 단독도 구별 능력이 낮으므로 자료 혼합만이 원인은 아니다.
통합 모델의 6종 AUC는 두 자료 모델보다 높아 손목 자료를 무조건 제외할 근거도 없다.

## 근거에 따른 다음 수정 순서

1. 수정된 전처리는 유지한다. 손목에서 품질이 양호한 구간과 나쁜 구간의
   성능/사용 가능한 구간 비율을 분리하고, 품질 필터가 AF를 과도하게 제외하지
   않는지 확인한다. 품질은 AF 정답으로 대신 정하지 않는다.
2. 파형 CNN과 별도로 PPG 맥박 간격/불규칙성 특징 기준 모델을 동일 분할로
   비교한다. 간격 추출의 실패율도 보고한다. ECG는 참조 점검에만 사용하고
   최종 PPG 예측 입력으로 혼입하지 않는다.
3. 학습률·seed 안정성과 더 긴 시간 관계를 다루는 모델을 검증군에서 비교한다.
   품질·정렬·잠정 라벨 해석도 병행 점검한다. 현재 결과만으로 특정 원인을
   확정하거나 복잡한 모델이 반드시 해결한다고 주장하지 않는다.
4. 후보 모델을 정한 뒤 민감도/특이도 절충 기준을 사전에 정하고 공통 임계값을
   검증군에서 선택한다. 새로운 외부 시험군으로 최종 평가한다.

첫 실행의 NumPy 문자열 메타데이터 재읽기 오류는 Python 문자열 저장으로 수정했다.
직접 생성한 완료 체크포인트는 weights_only=True와 제한된 NumPy 타입 허용으로
복구했으며 두 자료 학습을 반복하지 않았다. 복구 후 나머지 GPU 학습이 완료됐다.
